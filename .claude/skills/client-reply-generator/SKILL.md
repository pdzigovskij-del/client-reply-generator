# Client Reply Generator — скилл проекта

Локальное Streamlit-приложение: по сообщению клиента, типу ситуации, тону и
контексту компании генерирует 1–3 ответа через GigaChat API, определяет
реальный тип обращения и решает, нужно ли передать вопрос менеджеру.

Скилл описывает реальные файлы и поведение кода. Перед изменением файла
сверяйтесь с кодом, а не только с этим текстом: структура и детали могли
измениться.

## 1. Структура репозитория

```
client-reply-generator/
├── app.py                 # интерфейс Streamlit
├── reply_service.py       # настройки, вызов GigaChat, JSON, защита
├── compare_prompts.py     # прогон и сравнение версий промпта
├── check_gigachat.py      # диагностика доступа к GigaChat API
├── setup_certs.py         # загрузка сертификатов Минцифры
├── requirements.txt
├── .env.example           # шаблон настроек, без ключа
├── .env                   # локальный ключ, в git не попадает
├── .certs/                # локальные сертификаты, в git не попадают
├── .venv/                 # локальное окружение, в git не попадает
├── prompts/               # версии системного промпта, v1–v6
├── tests/cases.json       # 12 тестовых обращений и контекст компании
├── reports/               # результаты прогонов, сравнения и стабильность
├── docs/spec.md           # исходное описание проекта
├── images/                # скриншоты для README
└── .claude/skills/client-reply-generator/SKILL.md
```

Назначение файлов:

- `app.py` — только интерфейс: форма (сообщение, тип ситуации, тон, контекст,
  число вариантов), выбор версии промпта в боковой панели, подстановка
  примеров из `tests/cases.json`, вызов `generate_replies()` и показ
  результата. Бизнес-логики здесь нет.
- `reply_service.py` — вся работа с GigaChat: чтение `.env`, выбор промпта,
  сборка пользовательского сообщения, запрос в JSON-режиме API, резервный
  запрос без `response_format`, разбор JSON, проверка ответа на слова-обещания
  и запросы данных, повторная генерация.
- `compare_prompts.py` — последовательный прогон версий промпта на
  `tests/cases.json`, запись каждого запроса в `reports/results.jsonl` и сборка
  отчётов. Импортирует списки корней защиты из `reply_service.py`.
- `check_gigachat.py` — диагностика без интерфейса: получает токен, выбирает
  модель, делает простой запрос и проверяет структурированный ответ. Не
  печатает ключ. Коды выхода: `0` — успех, `1` — общая ошибка,
  `2` — ошибка SSL.
- `setup_certs.py` — скачивает корневой и промежуточный сертификаты НУЦ
  Минцифры с `gu-st.ru`, проверяет их и собирает
  `.certs/gigachat_ca_bundle.pem`. Ключи и `.env` не читает. Без `--force`
  существующий файл не перезаписывает.
- `prompts/v1_short.md` … `prompts/v6_final.md` — версии системного промпта.
  `available_prompt_versions()` находит все `*.md` в `prompts/` и сортирует
  имена лексикографически.
- `tests/cases.json` — `company_context` (вымышленная онлайн-школа «Вектор») и
  массив `cases`. У каждого обращения есть `id`, `message`,
  `situation_selected`, `tone`, `expected_situation`,
  `expected_needs_manager`, `checks`, `must_not`.
- `reports/` — `results.jsonl` (сырые записи по одному запросу на строку),
  `comparison_all.md`, `final_v6.md`, `stability.md`, `stability_2.md` и
  локальные `*.log`. Файлы `reports/*.log` исключены из git.
- `docs/spec.md` — постановка задачи и границы MVP.
- `images/` — готовые скриншоты, на которые ссылается README.

## 2. Развёртывание с нуля на Windows (PowerShell)

Требования: Python 3.10 или новее (проект проверен на 3.11.9), Git, ключ
авторизации GigaChat из личного кабинета developers.sber.ru.

Все команды выполнять из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
```

Зависимости закреплены в `requirements.txt`: `gigachat==0.2.4`,
`python-dotenv==1.2.4`, `streamlit==1.67.0`.

После `copy` пользователь сам открывает `.env` и заполняет
`GIGACHAT_CREDENTIALS`; для личного доступа оставляет
`GIGACHAT_SCOPE=GIGACHAT_API_PERS`. Остальные значения из шаблона:
`GIGACHAT_MODEL=GigaChat-2-Max`, `GIGACHAT_TEMPERATURE=0.3`,
`GIGACHAT_GUARD_RETRIES=3`, `PROMPT_VERSION=v6_final`,
`GIGACHAT_CA_BUNDLE=.certs/gigachat_ca_bundle.pem`.

**Claude Code не открывает и не печатает `.env`.** Заполнение ключа и правку
локальных значений выполняет пользователь.

Сертификаты Минцифры:

```powershell
.\.venv\Scripts\python.exe setup_certs.py
```

Скрипт печатает отпечатки SHA256. Для обновления существующего бандла:

```powershell
.\.venv\Scripts\python.exe setup_certs.py --force
```

Проверка доступа (запускать из корня: `check_gigachat.py` ищет `.env` через
`load_dotenv()` относительно текущего каталога):

```powershell
.\.venv\Scripts\python.exe check_gigachat.py --ca-bundle .certs\gigachat_ca_bundle.pem
```

При необходимости можно указать модель: `--model GigaChat-2`. Флаг
`--insecure` отключает проверку SSL и допустим только для явно запрошенной
локальной диагностики, не для рабочего кода.

Запуск интерфейса:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Открывается `http://localhost:8501`. Остановка — `Ctrl+C` в терминале. Если
порт занят: `--server.port 8502`.

Важно: `reply_service.load_settings()` вызывает
`load_dotenv(..., override=False)`. После изменения `.env` перезапустите
Streamlit, иначе процесс может продолжать использовать уже загруженные
переменные окружения.

## 3. Как вносить изменения

### Новая версия промпта

1. Создайте новый файл `prompts/vN_краткое_имя.md`. Не редактируйте старые
   версии, если они нужны для истории сравнений.
2. Проверьте, что файл — обычный текст системного промпта, как соседние
   версии. Версия автоматически появится в списке `available_prompt_versions()`
   и в боковой панели Streamlit.
3. Сравните новую версию с базовой **без** `--force`: уже записанные пары
   будут пропущены, выполнится только недостающая версия, а
   `reports/comparison.md` пересоберётся.

```powershell
.\.venv\Scripts\python.exe compare_prompts.py --versions v7_new,v6_final --pause 1.5
```

Критично: если запустить `compare_prompts.py` без `--versions`, используется
жёстко заданный список `PROMPT_VERSIONS` (`v1_short` … `v6_final`). Новая
версия `v7_*` в этот список не входит и не будет запущена. Всегда передавайте
`--versions` для новых файлов.

Параметры `compare_prompts.py`:

| Параметр | Поведение |
|---|---|
| `--versions v7_new,v6_final` | версии через запятую; отсутствующие файлы пропускаются с предупреждением |
| `--cases 3,6,7,9,11` | только указанные `id` из `tests/cases.json` |
| `--repeat 5` | повторить каждый выбранный запрос 5 раз; при значении больше 1 обязателен `--force` |
| `--force` | игнорировать уже записанные пары, помечать записи как `forced`/`repeat`; базовое сравнение такие записи не учитывает |
| `--pause 1.5` | пауза между запросами в секундах (по умолчанию 1.5) |
| `--retry-failed` | заново выполнить пары, записанные с ошибкой |

Куда пишутся результаты:

- каждый запрос сразу дописывается в `reports/results.jsonl`;
- без `--force` собирается `reports/comparison.md`;
- с `--force` и `--repeat 1` собирается `reports/final_v6.md`;
- с `--force` и `--repeat` больше 1 собирается `reports/stability.md`.

Имена отчётов в режиме `--force` фиксированы в константах и не зависят от
фактического списка версий. `comparison.md` в режиме `--force` не
пересобирается. Если нужна история прошлых отчётов, сохраните или
переименуйте их вручную до запуска.

Число запросов: `обращения × версии × repeat`, плюс до
`GIGACHAT_GUARD_RETRIES` перегенераций на каждый запрос, если сработала
защита. Прогон последовательный, без параллельных процессов.

### Смена основной версии промпта

Менять `PROMPT_VERSION` можно только после:

1. полного сравнения новой версии с базовой;
2. повторных запусков на рискованных обращениях, например:

```powershell
.\.venv\Scripts\python.exe compare_prompts.py --versions v7_new --cases 3,6,7,9,11 --repeat 5 --force --pause 1.5
```

3. ручной проверки `checks` и `must_not` и отчётов в `reports/`.

Локальное значение `PROMPT_VERSION` в `.env` меняет пользователь (Claude
Code не читает и не редактирует `.env`). Если меняется публичный шаблон,
обновите также `.env.example`.

Учтите: фактическая версия берётся из `.env`; если `PROMPT_VERSION` не задан,
код использует `DEFAULT_PROMPT_VERSION = "v6_final"` из `reply_service.py` —
то же значение, что и в `.env.example`. После смены перезапустите Streamlit.

### Защита от слов-обещаний в `reply_service.py`

После разбора ответа `_find_guard_roots()` приводит тексты ответов к нижнему
регистру и ищет корни:

- `GUARD_PROMISE_ROOTS`: `оператив`, `немедленн`, `срочн`, `скорее`,
  `быстрее`, `кратчайш`, `ближайшее время`, `завтра`, `сегодня же`,
  `гаранти`;
- `GUARD_DATA_ROOTS`: `номер карт`, `цифр карт`, `документ`, `паспорт`,
  `номер заказ`, `email`, `e-mail`.

`guard_root_in_text()` для одного слова проверяет вхождение подстроки, для
многословного выражения — регулярное выражение с `\w*` после каждого слова
(поэтому «номер заказ» ловит «номер заказа»). Совпадения нечувствительны к
регистру, потому что текст заранее переведён в нижний регистр.

Если что-то найдено:

1. в ответ добавляется инструкция переписать текст без найденных слов;
2. запрос повторяется с температурой `min(GIGACHAT_TEMPERATURE, 0.2)`;
3. число перегенераций ограничено `GIGACHAT_GUARD_RETRIES` (по умолчанию 3,
   допустимый диапазон после ограничения — 0…10);
4. если слова остались, `ReplyResult.warnings` заполняется, и интерфейс
   показывает предупреждение «Проверьте текст перед отправкой».

Защита ловит только эти корни и слова данных. Выдуманные факты, цифры и
неточные формулировки она не проверяет — это ограничение из README.
`compare_prompts.py` использует те же списки для пометок в отчётах, поэтому
изменение списков влияет и на приложение, и на анализ сравнения. Не ослабляйте
защиту без явной просьбы пользователя.

### Изменения в остальном коде

- Интерфейс меняйте в `app.py`, работу с API и промптами — в
  `reply_service.py`.
- Схема `RESPONSE_SCHEMA` и резервная инструкция `FALLBACK_INSTRUCTION`
  должны оставаться согласованными: по этой схеме разбирается
  `situation_type`, `replies`, `needs_manager`, `manager_reason`.
- Не добавляйте логирование `settings.credentials`. В коде уже есть
  маскирование ключа в `_describe_error()` — сохраняйте его.
- После правок без запросов к API полезно проверить синтаксис:

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py reply_service.py compare_prompts.py check_gigachat.py setup_certs.py
```

## 4. Как проверять ошибки

| Симптом | Причина и действие |
|---|---|
| `CERTIFICATE_VERIFY_FAILED`, `certificate verify failed`, `unable to get local issuer certificate` | Нет сертификатов НУЦ Минцифры. Выполните `setup_certs.py`, проверьте `GIGACHAT_CA_BUNDLE` в `.env`, перезапустите приложение. `check_gigachat.py` в этом случае завершается с кодом 2 и печатает подсказку. Не отключайте SSL в рабочем коде. |
| `GIGACHAT_CREDENTIALS не задан` | В `.env` пустой ключ. Кнопка «Сгенерировать» в Streamlit отключена, `generate_replies()` выбрасывает `ConfigError`. Пользователь копирует `.env.example` в `.env` и вписывает ключ. |
| `Модель вернула пустой ответ`, `choices пуст`, `ответ не является корректным JSON`, `В JSON отсутствует массив replies` | `InvalidModelResponse`. Сначала проверьте, что промпт требует JSON и что модель отвечает. Сервис автоматически повторяет запрос без `response_format` через `FALLBACK_INSTRUCTION`; если и это не помогло, показывает ошибку. Не логируйте ключ при разборе. |
| HTTP 400/422 в JSON-режиме | `_generate_once()` считает это поводом для резервного запроса без `response_format`. Если резервный тоже неудачен, ошибка показывается пользователю. |
| Лимиты GigaChat, 429 или долгие ответы | GigaChat работает в один поток, бесплатный тариф ограничен. Не запускайте несколько `compare_prompts.py` параллельно, не смешивайте массовый прогон с активной работой интерфейса, держите `--pause` не меньше 1.5 с. При массовом прогоне сначала подтвердите объём у пользователя. |
| Streamlit не отвечает или вкладка потеряла соединение | Процесс мог быть остановлен (`Ctrl+C`) или упал. Посмотрите терминал, перезапустите `streamlit run app.py`, при занятом порте укажите другой. После правки `.env` перезапуск обязателен. |
| `Версия промпта «…» не найдена` | Нет файла `prompts/<version>.md`. `ConfigError` перечисляет доступные версии. Проверьте имя файла и `PROMPT_VERSION`. |
| `Файл сертификата не найден` | Неверный путь в `GIGACHAT_CA_BUNDLE` или не выполнен `setup_certs.py`. Путь может быть относительным к корню проекта. |
| Отчёт `comparison.md` не обновился после `--force` | Это ожидаемо: в режиме `--force` собирается `final_v6.md` или `stability.md`. Для пересборки общего сравнения запустите без `--force`. |

## 5. Как обновлять README

- Любые цифры сравнения брать **только из `reports/`**: `comparison_all.md`,
  `final_v6.md`, `stability.md`, `stability_2.md` и `results.jsonl`.
  Не придумывать проценты, доли и «улучшения» и не переносить числа из
  памяти или из этого скилла.
- `reports/*.log` — локальные журналы, они исключены из git. Не ссылайтесь на
  них как на публичный источник.
- В README уже указаны модель, дата и условия прогонов. Если данные
  пересобраны, обновите числа и явно укажите, к какому отчёту и модели они
  относятся.
- Скриншоты лежат в `images/` с готовыми именами. Ссылки в README —
  относительные, например `images/01-main-screen.png`. Не выдумывайте новые
  имена и не обещайте скриншоты, которых нет.
- Если меняется поведение (новая версия промпта, защита, формат ответа),
  обновите соответствующие разделы README: «Что умеет», «Как выбирался
  промпт», «Известные ограничения», «Структура проекта».
- Не переписывайте исторические результаты прошлых версий без новых
  отчётов. Если отчёт отсутствует, так и напишите, а не подставляйте оценку.
- Раздел «Скилл для Claude Code» должен указывать на
  `.claude/skills/client-reply-generator/SKILL.md` и объяснять, что скилл
  подхватывается автоматически.

## 6. Подготовка к публикации

Текущий `.gitignore`:

```
.venv/
.env
.certs/
__pycache__/
*.py[cod]
reports/*.log
```

Проверки перед публикацией:

```powershell
git status --short
git ls-files
git ls-files --others --exclude-standard
git diff
git diff --cached
```

Убедитесь, что в git нет `.env`, `.certs/`, `.venv/` и `__pycache__/`.
Ищите ключеподобные строки только в отслеживаемых файлах, не открывая `.env`:

```powershell
git grep -n -I -E 'GIGACHAT_CREDENTIALS=[^[:space:]]+|Authorization: Bearer|PRIVATE KEY' -- . ':(exclude)*.md'
```

Дополнительно:

- проверьте, нет ли ключа в новых отчётах, логах, README и скриншотах;
- если `.claude/settings.local.json` появится, добавьте
  `.claude/settings.local.json` в `.gitignore` — это личные настройки, им не
  место в репозитории;
- ничего не коммитьте, не пушьте, не создавайте теги и релизы: пользователь
  делает это сам;
- если ключ всё же попал в git, не просто удаляйте файл — сообщите
  пользователю, что ключ нужно отозвать и заменить.

## 7. Правила для Claude Code

1. **Никогда не читать, не печатать и не пересказывать содержимое `.env`,
   `.certs/` и ключей.** Не выполняйте `Get-Content`, `cat`, `grep` и
   аналогичные команды по `.env`. Проверять существование файла можно, но
   значения ключа — нет. Для инструкций используйте `.env.example`.
2. **Не отключать проверку SSL в рабочем коде.** Запрещены
   `verify_ssl_certs=False`, `GIGACHAT_VERIFY_SSL=false` и `--insecure` как
   «исправление» ошибки. `--insecure` допустим только по явной просьбе
   пользователя и только для локальной диагностики.
3. **Не менять тестовые данные `tests/cases.json` без просьбы.** Там 12
   обращений, общий `company_context`, ожидаемые тип и эскалация, `checks` и
   `must_not`. При разрешённой правке сохраняйте структуру и валидный JSON,
   а после изменений предупредите, что сравнения нужно перезапускать.
4. **Не делать массовых запросов к GigaChat без подтверждения.** Сначала
   оцените число запросов (`обращения × версии × repeat` плюс возможные
   перегенерации защиты) и спросите пользователя. Прогоны только
   последовательные, с паузой.
5. **Не коммитить и не публиковать.** Никаких `git add`, `git commit`,
   `git push`, тегов и релизов без прямой просьбы. В этой задаче публикацию
   выполняет пользователь.
6. **Не ослаблять защиту и не удалять предупреждения** о словах-обещаниях,
   запросах данных и SSL ради «чистого» вывода.
7. **Сверяться с кодом.** Если задача затрагивает поведение, сначала
   прочитайте соответствующий файл; не полагайтесь на устаревшие отчёты или
   этот скилл как на единственный источник истины.
8. **Для запуска Python использовать `.\.venv\Scripts\python.exe`**, а не
   глобальный `python`, чтобы зависимости совпадали с `requirements.txt`.
